ROS2 Nodes & Topics

ROS2 applications are built from small, independent processes called nodes that communicate over named channels called topics, using a publish/subscribe pattern.

Minimal publisher node (Python)

import rclpy
from rclpy.node import Node
from std_msgs.msg import Float32

class AltitudePublisher(Node):
    def __init__(self):
        super().__init__('altitude_publisher')
        self.pub = self.create_publisher(Float32, 'altitude', 10)
        self.timer = self.create_timer(0.5, self.tick)

    def tick(self):
        msg = Float32()
        msg.data = 12.4
        self.pub.publish(msg)

rclpy.init()
rclpy.spin(AltitudePublisher())

Why the pub/sub model matters for robotics

Sensor drivers, state estimators, planners, and controllers can all run as separate nodes — potentially on different machines — and stay decoupled. A planner node never needs to know which specific sensor produced a pose estimate, only that it can subscribe to a topic that publishes one.

Node lifecycle basics

  • Unconfigured → node exists but hasn't allocated resources
  • Inactive → configured, but not yet processing data
  • Active → fully running, publishing/subscribing
  • Finalized → shutting down, resources released
