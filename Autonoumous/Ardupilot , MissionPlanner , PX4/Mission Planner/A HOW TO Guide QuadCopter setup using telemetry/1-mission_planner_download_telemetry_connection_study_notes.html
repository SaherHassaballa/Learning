🧠 Core Concepts

1. Ground Control Station (GCS) Telemetry vs. Direct RC Control Link
What is it? The separation of the vehicle's wireless links into two concurrent paths: an analog or digital Radio Control (RC) link for manual stick piloting (e.g., 2.4 GHz / ExpressLRS), and an independent, bidirectional wireless telemetry link carrying digital MAVLink data packets between the flight controller and the ground computer.
Why do we use it? A standard RC transmitter provides physical stick control but cannot easily visualize 3D terrain maps, artificial horizons, battery health metrics, or internal sensor health. The telemetry link enables real-time flight instrument monitoring, in-flight parameter tuning, and autonomous mission commanding from kilometers away without requiring tether cables.
How does it work? An onboard radio transceiver taps the flight controller's UART serial port (TELEM 1), modulates the serial binary packets into sub-gigahertz radio waves (915 MHz or 433 MHz), and transmits them over the air to a paired USB radio connected to the ground workstation.
Where is it used? All autonomous unmanned aerial systems (UAVs), search-and-rescue mapping drones, survey wings, and agricultural multirotors.
Example: When the pilot adjusts a parameter or plans a survey grid on the desktop, Mission Planner encodes the command into MAVLink and sends it over the telemetry link. The drone acknowledges receipt and updates its onboard non-volatile memory in real time.
Prerequisites: Basic familiarity with serial communication (Baud rate, UART TX/RX) and the ArduPilot ecosystem.
2. MAVLink Protocol & The Parameter Synchronization Handshake
What is it? Micro Air Vehicle Link (MAVLink); an ultra-lightweight, binary point-to-point communication protocol designed specifically for unmanned vehicles to transmit telemetry, navigation states, and hardware settings over bandwidth-constrained serial links.
Why do we use it? Plain-text data structures (such as JSON or XML) consume excessive RF bandwidth and lack structured checksum verification. MAVLink packages data into compact binary frames with rigorous Cyclic Redundancy Check (CRC) error detection.
How does it work? Upon clicking "Connect", Mission Planner initiates a handshake query. The flight controller responds by streaming all onboard registers (attitude, battery calibration, PID gains, failsafe triggers) into local PC RAM. Mission Planner displays a "Getting Params..." progress dialog until the parameter tree synchronizes completely.
Where is it used? Between the autopilot (Pixhawk / Cube / Durandal) and ground stations (Mission Planner / QGroundControl), as well as between the autopilot and onboard companion computers (Raspberry Pi via MAVProxy).
Relationship to other concepts: MAVLink operates on top of the physical serial RF link established by the SiK telemetry transceivers.
3. Over-The-Air Telemetry Transceiver Hardware Pairing (SiK Architecture)
What is it? A matched pair of sub-gigahertz radio modems consisting of an **Air Module** (wired to the drone's flight controller) and a **Ground Module** (plugged into the PC via USB Type-A).
Why do we use it? Standard Wi-Fi signals suffer from high latency and limited line-of-sight range ($50 - 100\,\text{m}$). SiK frequency-hopping spread spectrum (FHSS) transceivers operate at $915\,\text{MHz}$ or $433\,\text{MHz}$, delivering robust telemetry ranges spanning hundreds of meters to several kilometers.
How does it work? When powered, the modules scan for matching Network IDs (NetID) and frequency channels. An unlinked module indicates search mode via a **blinking green LED**. Once the radio frequency link locks, both modules switch to a **solid green LED**, indicating the physical RF transport layer is established.
Where is it used? Standard ArduPilot and PX4 telemetric interfaces.
4. Serial Baud Rate Matching (57600 Wireless vs. 115200 Wired USB)
What is it? The transmission speed (modulation rate in symbols per second) configured on the asynchronous serial UART communication link.
Why do we use it? Over-the-air radio frequency bandwidth is physically restricted. Transmitting data at USB cable speeds over wireless channels would cause massive packet loss, buffer overruns, and RF channel saturation.
How does it work? Direct wired USB connections to flight controllers operate at **`115200 baud`**. Standard wireless SiK telemetry radios operate strictly at **`57600 baud`**. Setting Mission Planner to `115200` when connecting via wireless radio modems causes framing errors, preventing packet decoding.
Where is it used? The connection dropdown bar in the upper-right corner of Mission Planner.

RF Output Stage Protection Rule:

🛠️ Practical Implementation: Step-by-Step Bench Commissioning

The video demonstrates an end-to-end configuration pipeline to install Mission Planner, verify hardware radio binding, and establish a live MAVLink session:

Step 1: Download & Install Mission Planner on Windows

  1. Open a web browser and navigate to the official ArduPilot download portal: ardupilot.org/planner.
  2. Locate and download the latest stable Microsoft Installer package: MissionPlanner-latest.msi.
  3. Launch the downloaded .msi setup wizard. Follow on-screen prompts using default installation directories.
  4. Device Driver Permissions: When Windows User Account Control (UAC) prompts for driver approvals, click Install to authorize the embedded FTDI, Silicon Labs CP210x, and PX4/STM32 Virtual COM Port drivers.
  5. Launch Mission Planner from the desktop shortcut.

Step 2: Power Up Drone & Verify Air Transceiver State

  1. Screw the rubber-duck antenna firmly onto the drone's Air Telemetry Module.
  2. Connect the telemetry cable harness from the radio module into the flight controller's TELEM 1 port.
  3. Power the drone's flight controller (in the video, the instructor powers the board via USB or power module).
  4. Observe the LED Status on the Drone:
    • The Air Module illuminates with a Blinking Green LED.
    • Meaning: The module is receiving clean DC power, but it has not located its paired partner transceiver over the air.

Step 3: Connect Ground Telemetry Radio to PC & Confirm Hardware Lock

  1. Screw the rubber-duck antenna firmly onto the Ground Telemetry Module.
  2. Plug the Ground Module directly into a native USB port on the Windows computer.
  3. Observe Physical Hardware Pairing: Within 1–3 seconds, the Ground Module and Air Module establish an RF lock:
    • The blinking green LED on the drone's Air Module stops blinking and transitions to SOLID GREEN.
    • The Ground Module on the computer also displays a continuous SOLID GREEN LED.
    • Significance: Physical RF hardware pairing is verified. Both modules share matching Network IDs and frequency-hopping parameters.

Step 4: Configure Port, Baud Rate & Connect in Mission Planner

  1. Look at the top-right corner of the Mission Planner window.
  2. Port Dropdown: Select the assigned COM port (e.g., COM4, or select AUTO to allow Mission Planner to detect the plugged telemetry module automatically).
  3. Baud Rate Dropdown: Set the baud rate dropdown strictly to 57600.
  4. Click the large green CONNECT button.
  5. Parameter Download Phase: Mission Planner sends a MAVLink query. A modal progress dialog titled "Getting Params..." appears on screen, reading configuration registers wirelessly from the flight controller into Mission Planner.
  6. Once complete, the button switches to a red DISCONNECT state, confirming an active session.

Step 5: Verify Live Telemetry on the Primary Flight Display (HUD)

  1. Navigate to the Flight Data screen (top-left tab).
  2. Artificial Horizon Check: Tilt the drone up, down, left, and right by hand on the bench. The virtual artificial horizon on the HUD must tilt dynamically in real time to reflect the drone's true spatial orientation.
  3. Heading & Altimeter Check: Rotate the drone horizontally; confirm the heading rose tracks smooth yaw rotation. Observe altitude and ground speed telemetry.
  4. GPS Lock Check: If the GPS puck is connected, verify satellite acquisition indicators on the HUD console.

⚠️ Common Problems & Solutions (Telemetry Troubleshooting)

Identified Problem Underlying Root Cause How to Identify Problem Engineering Remediation Why the Solution Works
Connection Hangs: "Timeout waiting for packets" Baud rate is configured to 115200 (the USB default) instead of 57600. Mission Planner hangs indefinitely at "Connecting Mavlink", then presents a timeout error. Change the baud rate dropdown in the top-right corner from 115200 to 57600 and click Connect. Matches the transmission rate of the SiK radio's internal UART buffer, eliminating framing errors.
Telemetry Radios Never Achieve Solid Green LED Air and Ground modules have mismatched frequency channels or conflicting NetID numbers. Both radios power up with blinking green LEDs and continue blinking indefinitely. Navigate to Initial Setup -> Optional Hardware -> SiK Radio; sync NetIDs and click Copy required to remote. Forces both transceivers onto the exact same frequency-hopping spread spectrum (FHSS) synchronization channel.
COM Port Dropdown Is Blank / Device Not Listed Windows did not install the Silicon Labs CP210x or FTDI USB-to-UART bridge virtual COM port driver. Device Manager displays an exclamation point under "Other Devices"; no COM port appears in Mission Planner. Re-run the Mission Planner .msi installer and approve all driver prompts, or download drivers directly from Silicon Labs. Registers the required USB serial driver, allowing Windows to enumerate the plugged radio as a valid serial port.
Session Drops Halfway Through "Getting Params..." Transmitter modules are placed too close to each other, overloading the RF receiver front-end (swamping). Progress bar begins downloading parameters, freezes around 15–30%, and disconnects. Separate the drone from the laptop by at least $1.5 - 2\,\text{m}$, or plug the Ground radio directly into a rear motherboard USB port. Prevents high RF input power from saturating the low-noise amplifier (LNA) on the receiving module.
Radio Module Disconnects When Motors Spin Up Air module placed adjacent to unshielded high-current LiPo power leads, ESCs, or video transmitter (EMI). Telemetry link is stable on the bench, but packet reception drops to 0% as throttle increases. Relocate the Air Telemetry Module onto an arm or fuselage side away from battery leads and ESC power wiring. Minimizes electromagnetic induction and RF interference on the receiver antenna stage.

📚 Technical Terminology

Term Technical Definition Why It Matters Practical Workshop Context
GCS (Ground Control Station) A desktop, laptop, or tablet software application that provides an interactive interface for autonomous vehicles. Serves as the mission control center to view telemetry, monitor battery depletion, adjust PID parameters, and plan missions. Mission Planner is the primary GCS software used for ArduPilot platforms.
MAVLink Micro Air Vehicle Link; a binary serial communications protocol tailored for small unmanned vehicles. Enables high-efficiency, low-bandwidth communication with CRC error-checking between autopilots and ground stations. The protocol that displays the "Getting Params..." progress dialog when establishing a connection.
SiK Radio An open-source telemetry radio firmware and hardware reference design created by 3DR. Provides long-range, frequency-hopping spread spectrum (FHSS) serial data transmission without requiring cellular data. Standard 915 MHz / 433 MHz telemetry transceivers bundled with Pixhawk kits.
Baud Rate The rate at which information is transferred across an asynchronous serial communication channel (symbols/sec). Mismatched baud rates prevent serial transceivers and ground stations from synchronizing, causing communication timeouts. Direct USB operates at 115200 baud; wireless SiK telemetry radios operate at 57600 baud.
COM Port (Virtual COM Port) A software abstraction in Windows that presents a physical USB bridge connection as a legacy serial communications port. Allows Mission Planner to send and receive UART serial streams to external USB devices like the ground radio. Selected via the dropdown in the upper-right corner of Mission Planner (e.g., `COM3`, `COM4`, or `AUTO`).
NetID A unique software identification number (0 to 499) stored inside SiK radio firmware registers. Prevents nearby radio telemetry pairs operating on the same frequency band from cross-talking or corrupting each other. Air and Ground modules must have identical NetID values to achieve a solid green pairing LED.

💡 Practical Takeaways: Workshop Rules & Field Procedures

  • 🟢 Antennas Screwed On First: Always verify that antennas are tightly fastened to both the air and ground modules before applying power to prevent damaging the RF output amplifiers.
  • 🟢 Verify Solid Green LEDs Before Connecting: Do not attempt to click "CONNECT" in Mission Planner while the telemetry LEDs are still blinking. The solid green indicator confirms hardware link lock.
  • 🔴 The Baud Rate Rule (57600 for Wireless): Never attempt to connect wireless telemetry radios at 115200 baud. Set the dropdown strictly to `57600`.
  • 🟡 Direct USB Ports for Ground Radio: Plug the ground telemetry radio directly into a native USB port on your PC motherboard; avoid cheap unpowered USB hubs that induce voltage sags.
  • 🟢 Auto COM Selection Works: If you are unsure which COM port Windows assigned to your ground radio, select `AUTO` in the dropdown menu; Mission Planner will scan available ports.
  • 🟢 Physical HUD Sanity Check: Always move the drone by hand on the bench after connecting. If you pitch the nose up, the artificial horizon HUD must reflect that pitch immediately.

❓ Questions & Answers (Self-Assessment)

Q1: Why must the baud rate in Mission Planner be set to 57600 when connecting via telemetry radios instead of 115200?
Wireless SiK telemetry radios have hardware-defined over-the-air RF bandwidth and internal serial UART buffers configured by default to 57600 baud. Setting Mission Planner to 115200 causes serial framing errors and timing mismatches, preventing MAVLink packets from being decoded. Direct USB cables use 115200 because a hardwired bus supports higher throughput.
Q2: What do a blinking green LED and a solid green LED signify on SiK telemetry modules?
A blinking green LED indicates that the module has power but is actively scanning frequency channels and searching for its paired transceiver. A solid green LED indicates that the air and ground modules have successfully locked onto each other using matching frequency-hopping channels and NetIDs, establishing the physical link layer.
Q3: What process is occurring when Mission Planner displays the "Getting Params..." progress dialog?
Mission Planner is querying the flight controller over MAVLink and downloading all operational parameters (PID gains, sensor calibration offsets, failsafe limits, flight modes) from the autopilot's onboard non-volatile memory into the local GCS workspace.
Q4: Why is it dangerous to power up telemetry radio modules without their antennas attached?
Operating a high-frequency RF transceiver without an antenna creates an impedance mismatch. The radio waves cannot be radiated into the air and reflect back into the output circuitry, dissipating as excess heat and permanently destroying the power amplifier (PA) stage.
Q5: How does a builder verify on the bench that telemetry communication is actively streaming live motion data?
By navigating to the Flight Data screen in Mission Planner and manually pitching and rolling the drone by hand. If telemetry is functional, the virtual artificial horizon on the Heads-Up Display (HUD) moves in real time to reflect the aircraft's orientation.
